# BotFramework 1.0.0

`1.0.0` is the first stable release of the package-only BotFramework surface.
The public API described in [`docs/api.md`](../api.md) is frozen for this
release.

## Highlights

- Stable tenant-aware contracts with opaque `TenantId`, `ScopeId`, `PlayerId`
  and `RequestId` values.
- Explicit transport metadata with `BotChannel.System` for background and
  transport-neutral execution.
- `CommandContext.Request` uses `RequestMetadata`; the legacy public
  `RequestContext` and `RequestContextAccessor` contracts are removed.
- Domain events are separate from executable `IGameEffect` values. Events are
  retained in `GameEffectSet.Events`, while `MaterializeEffects()` returns
  only executable effects.
- Generic `BotFramework.Text` normalization, tokenization, analysis, policy
  and effect primitives without censorship-specific business logic.
- Canonical tenant-aware REST routes, typed REST client, idempotency and RFC
  7807 error contracts.
- Deterministic game decisions, typed effects, tenant-aware scheduling and
  package consumer/template verification.

## Published package set

| Package | Purpose |
|---|---|
| `BotFramework.Contracts` | Tenant, transport, error, pagination and limiter contracts |
| `BotFramework.Sdk` | Module, domain, decision/effect, event and scheduling abstractions |
| `BotFramework.Testing` | Test fakes and in-memory fixtures |
| `BotFramework.Text` | Platform-neutral text normalization, analysis, policy and effect primitives |
| `BotFramework.Rest` | Tenant-aware REST middleware and module route contract |
| `BotFramework.Telegram.Abstractions` | Telegram update and tenant-resolution contracts |
| `BotFramework.Discord.Abstractions` | Discord tenant-resolution contracts |
| `BotFramework.Client` | Typed REST client and generated transport |
| `BotFramework.Scheduling.Abstractions` | Transport-neutral scheduled command contracts |
| `BotFramework.GameTemplates` | `dotnet new botframework-game` project template |

`BotFramework.Host`, `BotFramework.Telegram`, `BotFramework.Discord`,
`BotFramework.Scheduling.Quartz` and `BotFramework.Rendering` remain runtime
composition projects. They are built and tested in the repository but are not
published as stable package dependencies.

## Compatibility boundary

The `1.0.0` package surface is stable. Repository demonstration games and
application modules may continue to use compatibility layers internally, but
new external modules must depend only on the documented package contracts.
Behavior such as censorship, moderation, warnings, bans and delete policies
belongs to consumer modules and is not part of BotFramework.

## Verification

The release workflow verifies restore, Release build, tests, public API
baselines, package consumer smoke tests, template generation and NuGet package
validation before publishing packages and creating the GitHub Release.
