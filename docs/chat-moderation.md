# Модерация чатов

Документ описывает текущую реализацию автоматической модерации Telegram-чатов в модуле `ChatAdministration`.

Источник истины для поведения — код в `modules/ChatAdministration/ChatAdministration.Domain/Policies` и настройки конкретного чата. Значения ниже соответствуют настройкам по умолчанию, если для чата не применён другой preset и настройки не изменены.

## Кратко о принятии решения

Автомодерация обрабатывает сообщения пользователей в группах и супергруппах. Личные сообщения, сообщения ботов и service-сообщения в автоматическую модерацию не попадают.

Для каждого сообщения бот:

1. Определяет тип сообщения, текст или подпись, ссылки, упоминания, команды и факт пересылки.
2. Записывает сообщение в индекс и обновляет счётчики автора.
3. Проверяет все включённые правила.
4. Складывает баллы всех сработавших правил.
5. Если сумма достигла `DeleteThreshold`, создаёт moderation case и планирует действие.

При стандартных порогах и включённом `FloodPolicy.DeleteMessages`:

| Сумма баллов | Действие |
| --- | --- |
| `< 4` | Ничего не делать |
| `>= 4` | Удалить сообщение |
| `>= 7` | Удалить сообщение и выдать предупреждение |
| `>= 10` | Удалить сообщение и временно ограничить автора |
| `>= 20` | Удалить сообщение и заблокировать автора |

Пороги задаются в `ChatSettings.ModerationEscalation`. Если предупреждение достигает лимита, действие `Delete` может быть повышено до `Mute` или `Ban` согласно `WarningLimitAction`.

Важно: создание эффекта удаления дополнительно зависит от `FloodPolicy.DeleteMessages`. Несмотря на название, этот флаг сейчас является общим переключателем удаления для автоматических нарушений, а не только для flood. Если он выключен, бот всё ещё может выдать mute или ban, но сам message delete effect не создаётся.

Фактическое удаление выполняется фоновым effect worker через Telegram API. Бот должен быть администратором с правом `CanDeleteMessages`; иначе moderation case может завершиться ошибкой, а сообщение останется в чате.

## Правила

Все правила регистрируются провайдером `DefaultModerationRuleProvider`. Правило можно выключить или переопределить его score через `/rule`.

| ID | Баллы по умолчанию | Когда срабатывает | Состояние по умолчанию |
| --- | ---: | --- | --- |
| `flood` | 8 | Счётчик сообщений автора достигает `MaximumMessages` в пределах `Window`. | Включено: 6 сообщений за 10 секунд |
| `duplicate_message` | 6 | В истории найдено больше `maximumDuplicates` сообщений с тем же нормализованным текстом. | Включено, `maximumDuplicates = 1` |
| `links` | 7 | В сообщении найдена URL или text link, а режим ссылок запрещает её. | Правило есть, но режим `AllowAll` |
| `caps` | 4 | В тексте минимум 8 букв и не менее 70% из них — заглавные. | Включено |
| `forbidden_words` | 10 | Текст содержит одно из слов из `ForbiddenWordsPolicy.Words`. | Список пуст |
| `mention_spam` | 7 | Количество `@mention` и text mention превышает `MaximumMentions`. | Выключено |
| `forwarded_message` | 6 | Сообщение переслано, а политика пересланных сообщений включена. | Выключено |
| `media_type` | 6 | Тип сообщения находится в `MediaTypePolicy.BlockedTypes`. | Список запрещённых типов пуст |
| `new_member` | 3 | Автор находится в периоде усиленной политики после первого появления в чате. | Выключено |
| `command_spam` | 6 | Число Telegram-команд автора превышает `MaximumCommands` в пределах `Window`. | Выключено |

Баллы нескольких правил суммируются. Например, запрещённая ссылка с большим количеством заглавных букв может превысить порог за счёт двух нарушений.

### Flood

По умолчанию:

```text
Window = 10 секунд
MaximumMessages = 6
DeleteMessages = true
MuteDuration = 10 минут
```

Текущее сообщение включается в счётчик. Поэтому шестое сообщение автора в окне может стать нарушением. В счётчик входят сообщения любого поддерживаемого типа, включая фотографии, видео, стикеры и документы.

При Redis счётчик технически группируется по фиксированным временным bucket-ам размера `Window`. При fallback на in-memory store используется очередь с удалением устаревших сообщений.

### Повторяющиеся сообщения

Для сравнения текст приводится к нижнему регистру, а последовательности пробелов нормализуются. В штатном in-memory пути текущее сообщение уже присутствует в истории, поэтому при значении `maximumDuplicates = 1` второе одинаковое сообщение может сработать как duplicate.

В текущей Redis-реализации в `RecentMessageHashes` возвращается только hash текущего сообщения. Поэтому обнаружение повторов через Redis ограничено и может не сработать для предыдущих одинаковых сообщений. Это особенность реализации, а не отдельная настройка чата.

### Ссылки

Ссылка определяется по Telegram entities (`Url` или `TextLink`) либо по шаблону `http://`, `https://` или `www.`.

Режимы:

- `AllowAll` — ссылки разрешены;
- `DenyAll` — ссылки запрещены для всех;
- `AllowTrusted` — ссылки разрешены участникам с ролью `Trusted`.

Поле `AllowedDomains` присутствует в модели политики, но текущая `LinkRule` его не использует.

### Запрещённые слова

Проверка выполняется как поиск подстроки, а не как поиск отдельного слова. По умолчанию регистр игнорируется. Например, слово `scam` совпадёт с `SCAM` и `scammer`.

## Почему удаляются фотографии

Фотография сама по себе не запрещена настройками по умолчанию. При нормализации она получает `ContentType = Photo`, а её подпись используется как текст сообщения.

Фотография может быть удалена по нескольким причинам:

1. Она стала шестым сообщением автора в flood-окне.
2. В подписи есть запрещённая ссылка.
3. В подписи сработало правило caps или forbidden words.
4. Фотография переслана при включённой политике forwarded messages.
5. В `BlockedTypes` явно добавлен `Photo`.

Правило `media_type` проверяет только наличие типа в `BlockedTypes`; по умолчанию `BlockedTypes` пуст. В текущем Telegram-интерфейсе нет команды для добавления `Photo` в этот список, но правило можно отключить командой `/rule media_type off`, если типы медиа были настроены через другой административный путь.

## Настройки в Telegram

Команда `/settings` без аргументов показывает основные текущие значения.

Поддерживаются:

```text
/settings automod on|off
/settings flood <1..1000>
/settings links allow|deny
/settings mentions <1..1000>
/settings forwarded on|off
/settings newmember on|off
/settings commandspam <1..1000>
/settings captcha on|off
/settings welcome on|off
/settings goodbye on|off
/settings logchat <chat_id>|off
```

Команда `/rule` предназначена для включения и выключения отдельных правил и для изменения их score:

```text
/rule <rule_id> on|off [score]
```

Допустимые `rule_id`:

```text
flood
duplicate_message
links
caps
forbidden_words
mention_spam
forwarded_message
media_type
new_member
command_spam
```

Для этих команд требуются права администратора чата согласно политике Chat Administration.

## Preset-ы

SuperAdmin может применить preset в `/admin/chat-administration`.

### `default`

- автомодерация включена;
- flood: 6 сообщений за 10 секунд;
- пороги: delete 4, warning 7, mute 10, ban 20;
- ссылки разрешены;
- mention spam, forwarded, new member и command spam выключены настройками;
- forbidden words и blocked media types пусты.

### `relaxed`

- flood: 12 сообщений за 15 секунд;
- пороги: delete 8, warning 12, mute 18, ban 30;
- правила `duplicate_message` и `caps` выключены;
- mute длится 5 минут.

### `strict`

- flood: 4 сообщения за 10 секунд;
- пороги: delete 3, warning 5, mute 8, ban 14;
- ссылки запрещены;
- максимум 3 упоминания;
- пересланные сообщения считаются нарушением;
- для новых участников действует окно 30 минут;
- command spam: более 3 команд за 30 секунд;
- включена CAPTCHA для новых участников.

Strict preset не добавляет `Photo` в `BlockedTypes`, поэтому сам по себе не запрещает фотографии.

### `disabled`

Выключает manual moderation, automatic moderation и CAPTCHA.

## Другие пути удаления

Автомодерация — не единственный источник удаления сообщений:

- `/purge` вручную удаляет сообщения, найденные в индексе, если у исполнителя есть право `MessagesPurge`;
- CAPTCHA удаляет своё challenge-сообщение после успешного завершения, окончательной ошибки или истечения срока, если `DeleteChallengeAfterCompletion = true`;
- retention cleanup удаляет записи из таблиц индекса, audit log и callback state. Он не удаляет уже опубликованные Telegram-сообщения;
- поля `DeleteCommandMessages` и `DeleteServiceMessages` присутствуют в настройках и strict preset, но текущий обработчик сообщений не использует их для удаления. Service-сообщения вместо этого пропускаются автоматической модерацией.

## Где посмотреть причину

Для каждого срабатывания создаётся moderation case. Его `Reason` содержит коды нарушений, например:

```text
flood
media_type
link_policy, caps
```

Администратор может использовать `/cases` и `/case`, а SuperAdmin — раздел Chat Administration в BFF. Это позволяет отличить удаление по flood от удаления по `media_type` или подписи фотографии.
